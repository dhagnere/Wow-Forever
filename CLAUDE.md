# La Taverne Éternelle — consignes pour Claude Code

Site de fans francophone non officiel consacré à World of Warcraft: Forever. Next.js 16 (App Router), PostgreSQL, hébergé chez Scalingo. Les articles sont signés Jobwow, mort-vivant de la Horde et tavernier ; sa classe n'est jamais précisée, ni dans les textes ni dans les consignes de l'IA (avatar : `visuels/jobwow.svg`, dessin d'un personnage au chapeau étoilé). La Taverne s'adresse aux deux factions : la fierté de la Horde reste un clin d'œil, jamais un parti pris. Le nom de code interne de l'avis reste `avis_silfax` / `avisSilfax` : ne pas renommer la colonne.

## Organisation

| Dossier | Rôle | Liberté |
|---|---|---|
| `app/(site)/`, `components/`, `app/globals.css`, `content/` | Pages publiques, habillage, contenu des pages piliers | Libre |
| `app/admin/` | Espace de relecture `/admin/veille` | Libre sur l'ergonomie, garde-fous intacts |
| `modules/veille/` | Collecte, classement, rédaction IA, articles, relais Facebook, sessions, base d'objets (`objets/`), statistiques d'audience (`statistiques/`) | Module cloisonné |
| `content/calendrier.ts` | Dates clés (page Calendrier et fichier d'agenda, en français et en anglais) | Libre ; une date non annoncée reste `null` ; reporter chaque changement dans le champ `en` |
| `visuels/` | Dessins de l'enseigne, de la chope et de Jobwow ; `npm run visuels:generer` refait les PNG | Libre |
| `config/sources.ts` | Sources surveillées | Libre |
| `config/taxonomie.ts` | Rubriques et pages piliers | Ajouter librement ; ne pas renommer un slug déjà publié |

## Limites du module

- Les pages (`app/`, `components/`, `lib/`, `proxy.ts`) n'importent **que** `@/modules/veille` (fichier `modules/veille/index.ts`). Jamais un fichier interne du module. Un besoin nouveau = un export de plus dans `index.ts`.
- Le module n'importe rien de `app/` ni de `components/`. Il peut lire `config/`.
- Seul `db/schema.sql` modifie la structure de la base. Il doit rester idempotent (`IF NOT EXISTS`) : il est rejoué à chaque déploiement.

## Garde-fous à ne jamais affaiblir

1. **Avis obligatoire.** Aucun article ne se publie sans « L'avis de Jobwow » rédigé (80 caractères minimum, sans texte à remplacer entre crochets). La règle est appliquée deux fois : `articles/publication.ts` et la contrainte `avis_obligatoire` de la base. Ne pas retirer, assouplir ni contourner l'une ou l'autre, ni publier par une requête SQL directe. L'IA peut proposer un avis (`avis_propose`, affiché dans l'éditeur) ; il n'entre dans `avis_silfax` que par un clic de Jobwow. Ne jamais remplir `avis_silfax` automatiquement.
2. **Filtrage du HTML.** Tout contenu affiché passe par `markdownVersHtml` / `nettoyerHtml` (`rendu/html.ts`). Pas de `dangerouslySetInnerHTML` sur du contenu non filtré. Seules les vidéos YouTube sont intégrables.
3. **Accès réservé.** Tout `/admin` exige une session signée : `proxy.ts` à l'entrée, `exigerAdmin()` en tête de chaque page et de chaque action serveur. Une nouvelle page ou action d'administration appelle `exigerAdmin()`.
4. **Droit d'auteur.** Les consignes de rédaction (`redaction/consignes.ts`) imposent un article neuf, une seule citation courte, des sources créditées et aucune image copiée. Le ton peut être ajusté ; ces règles, non. Une image ne s'envoie qu'avec la case de déclaration des droits cochée, et passe toujours par `enregistrerImage` (réencodage, métadonnées retirées). Une image d'en-tête exige sa description, et aucun article ne se publie sans image d'en-tête (`verifierPublication(…, { exigerImage: true })` dans `publier` ; un article déjà en ligne reste modifiable sans). L'éditeur propose des images d'en-tête (`lib/imagesProposees.ts`) choisies parmi les illustrations que le site possède (visuels du kit officiel Blizzard, écrans de chargement, cartes) : huit propositions d'après les lieux, donjons et classes cités, puis la galerie de toutes ces illustrations, avec un filtre par nom (`toutesLesImages`) ; la première est cochée d'office pour un brouillon sans image, mais n'est ajoutée qu'à l'enregistrement, case cochée, par `enregistrerImage`. Une seule source extérieure, toujours au choix de Jobwow, jamais par l'IA ni automatiquement : le kit officiel de Blizzard (presse ou sites de fans), téléchargé à la main puis importé par `npm run kit:blizzard -- <dossier>` (`config/kit-blizzard.ts`, `public/images/kit/`, crédit « © Blizzard Entertainment »). Ne jamais aller chercher d'image ailleurs : ni sur les sources, ni par un moteur de recherche, ni sur un autre site. La légende de l'image (`image_legende`, affichée avant le crédit) est proposée par l'IA (`proposerLegende`, consignes `CONSIGNES_LEGENDE`), d'office à l'ouverture d'un brouillon sans légende, puis gardée, reprise ou effacée par Jobwow ; elle se traduit avec l'article. L'image du post Facebook est par défaut l'image de l'article (aperçu du lien) ; Jobwow peut en choisir une parmi les mêmes propositions (`imageFacebookProposee`), ajoutée seulement case cochée, par `enregistrerImage`.
5. **Les réseaux suivent le site.** Le relais (Facebook, Reels, Instagram, TikTok) ne publie que des articles déjà en ligne, avec un lien ou un renvoi vers le site (jamais vers la source), entre 8h et 22h (Paris), trois publications par heure et par réseau au plus. Les jetons d'accès restent en base ou dans les variables d'environnement, jamais affichés ni journalisés. Tout texte destiné à un réseau social passe par `texteReseau` (`reseaux/textes.ts`), qui ajoute la phrase d'appel unique de `config/reseaux.ts` : ne pas la dupliquer ni la contourner. L'accroche et le texte du post Facebook sont proposés par l'IA (`proposerTexteFacebook`, consignes `CONSIGNES_FACEBOOK`, nettoyés par `nettoyerTexteFacebook` : ni lien, ni mot-dièse, ni crochets), d'office pour un brouillon sans texte, puis gardés ou repris par Jobwow. Facebook interdit de pré-remplir « Quoi de neuf ? » depuis un lien de partage : le bouton « Partager sur Facebook » (`components/PartageFacebook.tsx`, page de l'article et éditeur) copie au clic le texte de `texteReseau`, puis ouvre la fenêtre de partage, où il suffit de coller. Dans l'éditeur, le bouton « Publier depuis la Page Facebook » (`page={SITE.facebook}`) copie le même texte et ouvre la Page elle-même, la fenêtre de partage bloquant souvent quand on publie en tant que Page.

## Lettre

Le site garde lui-même les abonnés (module `lettre/`, tables `lettre_abonnes`, `lettre_envois`, `lettre_file`) ; Resend ne fait que remettre les messages (`courriel/resend.ts`, `RESEND_API_KEY`, `COURRIEL_EXPEDITEUR`, mode d'emploi dans `LETTRE.md`). Double validation : l'adresse attend en base, le lien de confirmation (jeton gardé par son empreinte, 48 heures) mène à `/lettre/confirmation/`, où un bouton confirme (un robot qui ouvre le lien n'inscrit personne) ; une demande jamais confirmée est effacée au bout de sept jours. La réponse à une inscription est la même que l'adresse soit nouvelle ou déjà abonnée. Chaque Lettre porte un lien de désinscription signé (HMAC, `SESSION_SECRET`, `/lettre/desinscription/`) et l'en-tête de désinscription en un clic (`List-Unsubscribe`, `/api/lettre/desinscription/`) ; se désinscrire efface l'adresse. Le corps de la Lettre (Markdown) passe par `markdownVersHtml`. Les numéros s'écrivent dans `/admin/lettre` (`exigerAdmin()`), avec essai obligatoire avant lancement ; le premier lot part au lancement, puis `npm run veille:lettre` (chaque heure, dans `npm run veille:horaire`) envoie par lots de 50 dans la limite de `LETTRE_PLAFOND_JOUR` (80 par défaut, sous les 100 messages par jour de l'offre gratuite de Resend). Les adresses ne sont jamais journalisées. Les numéros déjà lancés se relisent dans « Mon compte » (section « Les Lettres de Jobwow », `/en/account/` pour l'édition anglaise), pour tout joueur connecté : `lettresParues(langue)`, corps rendu par `markdownVersHtml`, jamais un brouillon.

## Statistiques d'audience

Mesure maison, sans cookie ni stockage dans le navigateur (`components/Mesure.tsx` → `/api/mesure` → `statistiques/collecte.ts`). Ne jamais enregistrer l'adresse IP, un identifiant durable ni les paramètres d'adresse : le visiteur est une empreinte salée (`STATS_SEL`) recalculée chaque jour. Les refus de suivi du navigateur (DNT, GPC) sont respectés ; les données de plus de 13 mois sont effacées. Le pays est estimé d'après le fuseau horaire du navigateur (`statistiques/fuseaux.ts`, table IANA), jamais d'après l'IP ; la langue du navigateur est réduite à sa forme courte (`fr-FR`). Seule exception aux paramètres d'adresse : le terme tapé dans la recherche du site ou de la base d'objets, envoyé par la page (`data-recherche`), filtré par `termeMesurable` (ni adresse électronique, ni lien, ni nombre de cinq chiffres ou plus) et gardé dans `stats_recherches`, sans lien avec le visiteur. Les pages introuvables se signalent par `data-introuvable` (page 404). Tableau de bord : `/admin/statistiques` (`exigerAdmin()`). Un bouton se mesure en lui donnant un attribut `data-cta="nom-court"`. Google Tag Manager (conteneur `GTM-5KX55C25`, `SITE.gtmId`, `NEXT_PUBLIC_GTM_ID` le remplace ou `off` le coupe) se charge sur toutes les pages publiques, françaises (`app/(site)/layout.tsx`, page 404 `app/not-found.tsx`) et anglaises (`app/en/layout.tsx`), par `MesureAudience` en mode consentement : tout refusé par défaut, rien n'est mesuré avant l'accord donné dans `BandeauCookies` (Accepter et Refuser au même niveau, en français ou en anglais) ; le lien « Gérer les cookies » / « Manage cookies » du pied de page rouvre le choix. Une nouvelle page publique hérite de ces mises en page ; ne jamais coller le script Google en dur ni le charger avant le consentement. L'administration n'est pas mesurée.

## Revue de veille

Dans la revue (`/admin/veille/revue/`), un sujet dont la source la plus récente a plus de 3 jours est retiré de la liste et de la rédaction (`sujetEncoreFrais`, `AGE_MAX_SUJET_JOURS` et `THEMES_SANS_LIMITE_AGE` dans `config/sources.ts`), sauf les sujets de classes. Les dossiers de référence gardent leurs 60 jours.

## Tableau des guildes

Contenu déposé par des inconnus (`guildes/`). Chaque fiche passe par la relecture de `/admin/guildes` avant publication ; une modification repasse en relecture. Les textes sont affichés comme du texte brut (jamais en HTML), sans lien : les seuls liens sont l'invitation Discord et un site https, validés par `validerFiche` et rendus en `rel="nofollow ugc"`. Le lien de modification est un secret : seule son empreinte est en base, la page `/guildes/modifier/…` n'est ni indexée ni mesurée.

## Base d'objets

Importée des fichiers du jeu par wago.tools (`objets/wago.ts`, produit `wowf`), en français. L'import remplace tout en une transaction et s'arrête si moins de 1 000 objets sont lus. Les objets internes (tests, équipement des monstres, objets périmés, niveau requis au-delà de 60) sont écartés par `objetInterne` (`objets/conversion.ts`). Les icônes ne sont demandées à wago.tools que pour un objet connu de la base, puis gardées en cache dans `objets_icones`. Garder le crédit wago.tools et la mention Blizzard (pages de la base et mentions légales). Les icônes de classes et de races, les écrans de chargement et les cartes du monde (`public/images/jeu/`) viennent de la même source : `npm run icones:jeu`, `npm run ecrans:jeu` et `npm run cartes:jeu` les refont. Les pages de lieux `/cartes/<lieu>/` relient les noms des guides (`content/reference.ts`) aux cartes par `lieuParNom` (`lib/cartes.ts`) : un nom qui diffère du jeu va dans `ALIAS` (le test `tests/cartes.test.ts` le signale). La liste des écrans est dans `config/ecrans.ts`, le choix de l'écran de chaque page dans `lib/ecrans.ts`. Chaque illustration porte la mention « © Blizzard Entertainment ».

## Sorts et talents des classes

Lus dans les fichiers du jeu par `npm run sorts:jeu` (`sorts/conversion.ts`), sans base de données : le script écrit `content/sorts-jeu.json` et les icônes `public/images/jeu/sorts/`, affichés sous chaque classe (`components/SortsClasse.tsx`, un onglet par spécialisation). Une spécialisation associe un arbre de talents à la ligne de compétence de son école (`SPECIALISATIONS`). Les descriptions du jeu sont des modèles (`$s1`, `$d`, `${…}`) remplis par `sorts/description.ts` pour un personnage sans talent ni équipement ; ce qui dépend de la puissance d'attaque ou de l'arme s'affiche « X ». Chaque talent garde la description de chacun de ses rangs (`descriptions`, null quand le rang manque) : Forever ne publie aujourd'hui que 102 rangs au-delà du premier, les autres s'afficheront après un nouveau `npm run sorts:jeu`. Ne pas les compléter par Classic Era (valeurs des talents à zéro dans ses fichiers) ni par Wowhead. Les familiers suivent (`components/FamiliersClasse.tsx`) : familles de bêtes du chasseur et démons du démoniste, lus par `CreatureFamily` et leurs lignes de compétence ; les techniques communes des bêtes sont celles que le Dressage des bêtes enseigne. Les familiers n'ont pas d'arbre de talents dans les fichiers de Forever (seuls les 27 arbres des classes existent) ; la loyauté du chasseur vient de `PetLoyalty`. Un talent dont le sort n'est pas publié reste dans l'arbre sous `TALENT_NON_PUBLIE`.

Traits raciaux : lignes de compétence raciales (`LIGNES_RACIALES`), affichés sur `/races/` (une carte par race, ancre `#<race>`) et sur la fiche Skyborne (`components/TraitsRaciaux.tsx`). Un trait qui change selon la classe garde une variante par groupe de classes. La faction des deux capacités propres aux Skyborne vient de la bêta (`SKYBORNE.factionsCapacites`), les fichiers ne la donnant pas.

Calculateur de talents : `/classes/<classe>/talents/` (`components/CalculateurTalents.tsx`), règles dans `lib/calculateur.ts` (51 points au niveau 60, 5 points par palier, prérequis au maximum, retrait refusé s'il casse l'arbre). Le build est dans l'adresse (`?build=0503-…-…`, un chiffre par talent dans l'ordre palier puis colonne) : changer l'ordre ou le nombre de talents d'un arbre casse les liens déjà partagés. Relancer le script à chaque version du jeu ; il s'arrête si moins de 200 sorts sont lus.

## Caractéristiques et sources des objets

Les recettes des métiers (« Fabriqué par », « Utilisé pour fabriquer », « Apprend à fabriquer ») viennent aussi des fichiers du jeu, lues à l'import par `convertirRecettes` (table `objets_recettes`). Les bonus, l'armure et les dégâts sont calculés à l'import par `objets/caracteristiques.ts`, comme le fait le jeu (budget du niveau d'objet × part de chaque bonus) ; les légendaires gardent des dégâts propres, non calculés. « Où le trouver » vient des bases libres CMaNGOS classic-db (GPL v3) et AzerothCore (noms français, GPL v2) : `npm run base:butin` produit `objets/donnees/butin.json.gz`, lu par `ouTrouver`. Les positions sont converties sur les cartes du jeu, la zone d'un point étant tranchée par les zones d'exploration des cartes. Ne pas récupérer ces données sur Wowhead ou un site équivalent : leurs bases sont protégées. Garder le crédit sur les fiches et dans les mentions légales.

## Guides de quêtes

`npm run base:quetes -- <dump CMaNGOS> <db_world AzerothCore>` écrit `content/quetes-jeu.json` : quêtes de classe en chaînes (`/guides/quetes-de-classe/<classe>/`) et parcours de 1 à 60 par faction (`/guides/parcours/`). Seules les quêtes de l'Azeroth d'origine encore présentes dans les fichiers de Forever (table `QuestV2`) sont gardées. Ne reprendre aucun texte de quête : titres et noms seulement, objectifs rédigés à partir des données (« Rapporter 5 × … », « Vaincre 10 × … »). Ne pas s'appuyer sur des guides commerciaux (Zygor, etc.) ni sur Wowhead. Les outils communs aux scripts des bases libres (lecture du dump, positions sur les cartes, priorité aux capitales) sont dans `scripts/_bases-libres.ts`.

## Comptes joueurs et guide de 1 à 60

Un joueur crée son compte sur `/compte/` (pseudo, adresse, mot de passe) ; le même formulaire l'inscrit à la Lettre s'il coche la case, toujours en double validation (`lib/lettre.ts`, voir « Lettre » plus bas). Module `joueurs/` : mot de passe en empreinte scrypt salée (`motdepasse.ts`), jamais en clair ni journalisé ; sessions et liens de réinitialisation gardés par l'empreinte de leur jeton ; cinq erreurs de mot de passe bloquent le compte quinze minutes ; cinq créations de compte par jour et par connexion au plus. Le cookie `taverne_joueur` (HttpOnly, SameSite=Lax, 30 jours) est un cookie de service : ne jamais s'en servir pour la mesure d'audience. La suppression du compte efface tout (ON DELETE CASCADE). Inscriptions visibles dans `/admin/comptes` (`exigerAdmin()`, `listerComptes`, `abonnesSansCompte`) : pseudo, adresse, dates, état de la Lettre, et abonnés à la Lettre sans compte ; ces adresses ne s'affichent que là. Le test `tests/admin.test.ts` vérifie que chaque page et chaque action serveur d'administration commencent par `exigerAdmin()`. Le mot de passe oublié part par Resend (`lib/courriel.ts`, `courriel/resend.ts`).

Guide de 1 à 60 par race et classe : `/guides/parcours/<race>/<classe>/` (`components/GuideParcours.tsx`, données `content/guide-jeu.json` produites par `npm run base:quetes`, adaptation dans `lib/guide.ts`). L'ordre de passage est calculé par `planifier` (`lib/guide.ts`), qui simule le joueur : une quête se prend à son niveau et après le rendu de sa quête préalable, ses objectifs se font au secteur de ses cibles, elle se rend ensuite ; on va toujours au plus proche (cible, PNJ à qui rendre, PNJ qui propose). Le test `tests/guide.test.ts` vérifie cet ordre pour chaque race et chaque classe : ne pas l'affaiblir. Les cibles (monstres à vaincre, monstres et objets du décor qui donnent l'objet demandé) sont placées par `base:quetes` (`cib`). Sur la carte, les PNJ d'un même village forment un point ; seules l'étape en cours et les huit suivantes sont tracées, en flèches d'une étape à la suivante ; la case « Monstres et objets sur la carte » affiche les cibles d'une quête et des flèches donneur → cibles → receveur. Les cartes se zooment (molette autour du curseur, deux doigts, double clic, boutons + − ⤢) et se déplacent au glisser : calculs dans `components/zoomCarte.ts` ; pastilles, épaisseur des flèches et pointes gardent leur taille à l'écran ; les flèches sont des courbes, pour qu'un aller et un retour entre deux mêmes points ne se superposent pas. La progression se sauvegarde par `/api/progression/` (joueur connecté seulement, journal par jour dans `progression_jours`) ; sans compte, une fenêtre propose d'en créer un, une fois par visite. Les pages du guide restent statiques : l'état du joueur est lu par le navigateur, pas à la compilation. Le guide est la première fonction de l'accueil (section `#guide-1-60`, choix par classe puis race, `components/ChoixGuide.tsx`). Relecture en jeu : `/admin/guides/` (`exigerAdmin()`) liste les 56 guides, et `/admin/guides/<race>/<classe>/` reprend les étapes de `planifier` zone par zone, avec pour chacune une case « vérifié en jeu » et une remarque (table `guides_relecture`, module `guides/relecture.ts`, clé d'étape « prendre:<id de quête> ») ; les remarques servent à corriger le calcul et ne s'affichent jamais sur le site. On relit en jouant sans guide commercial, jamais en recopiant l'ordre d'un guide payant. Un bloc de remarques (« prendre:4641 | oui | remarque », une étape par ligne, `lireBlocRemarques`) se colle dans « Importer des remarques ». Quêtes ajoutées par Forever, inconnues des bases libres (les fichiers n'en donnent que le numéro) : saisies à la main dans `content/ajouts-forever.ts` (ids 9100001 et suivants, zone, donneur et receveur avec leurs coordonnées, objectifs rédigés avec nos mots, source de l'observation), insérées par `avecAjoutsForever` ; sans cibles relevées, l'objectif porte « [secteur à relever en jeu] ». Parcours relevés en jeu (`content/parcours-releves.ts`) : l'ordre réellement joué dans une zone, par race (et classe si besoin), relevé jusqu'au 8 novembre 2026 sur des parties filmées sans guide commercial, et plus complété depuis (les vidéos ne servent plus aux guides ; les routes jouées passent par RouteProbe et l'addon EternalRoutes) ; `ordreDuGuide` le place en tête de la zone puis reprend l'ordre de `planifier` pour le reste (pages du guide en français et en anglais, relecture où ces étapes sont marquées « relevé en vidéo ») ; `tests/parcours-releves.test.ts` vérifie que chaque étape existe et que l'ordre reste jouable. Les vidéos de Jobwow servent désormais à YouTube et à la Lettre seulement (`VIDEOS.md`) : rien n'en est repris dans les guides, `parcours-releves.ts`, `ajouts-forever.ts` ni la relecture. Chaque page de zone (`/cartes/<lieu>/`, et `/zones/<slug>/` quand le lieu a une carte) propose les guides qui y passent (`guidesPassantPar`), avec un lien vers `/guides/parcours/<race>/<classe>/#zone-<lieu>`, qui ouvre directement cette zone. Skyborne : deux « races » du guide (`skyborne-alliance`, `skyborne-horde`), avec les classes de leur ordre (`SKYBORNE.ordres`) ; départ sur l'île de Zéphras, puis la route de la faction à partir du niveau 10, quêtes ouvertes à toute la faction seulement. Les fichiers du jeu ne donnent aucune quête de l'île : elles se saisissent à la main dans `content/zephras.ts` (ids 9000001 et suivants, objectifs rédigés avec nos mots), avec ses niveaux et son point de sortie ; tant que la liste est vide, l'étape montre la carte et ses lieux (`content/zephras-jeu.ts`, produit par `npm run zephras:jeu`) avec un message.

Chaîne : `https://www.youtube.com/@TheWowtoon` (« Taverne Eternelle », identifiant `UCJGfW3y0BO7Dojj-kYh-_9g`), valeurs par défaut de `SITE.youtube` et `SITE.youtubeChaine` ; `NEXT_PUBLIC_YOUTUBE_URL` (« off » masque les liens du pied de page, du Carnet et d'« À propos ») et `YOUTUBE_CHANNEL_ID` les remplacent si besoin. Montage sur le PC de Jobwow, jamais sur le serveur : `npm run carnet:video -- <dossier Warcraft Recorder>` range les vidéos dans l'ordre chronologique, les regroupe par séance (plus de 30 minutes d'écart : nouvelle séance), les assemble sans réencodage (ffmpeg, copie des flux) et écrit pour chacune un `.youtube.txt` (titre de 100 caractères au plus, description, chapitres). Une Lettre par semaine, en français et en anglais : `content/lettres-preparees.ts`, listée dans `/admin/lettre` (« Brouillons préparés »), importée en brouillon par un clic (`importerPreparee`) ; essai et lancement restent à Jobwow. Contrôles (limites de YouTube, chapitres, paires de langues) dans `tests/videos-preparees.test.ts`.

## Addon EternalRoutes

L'addon de jeu (guide pas à pas, dossier `EternalRoutes`, hors du dépôt) reçoit les 56 guides de 1 à 60 du site : `npm run addon:guides -- <dossier de l'addon>` écrit `Guides/site/<race>-<classe>.lua` (même ordre que les pages : `ordreDuGuide`), `Maps.lua` (carte du jeu par nom de zone, identifiant UiMap de `content/cartes-jeu.ts`) et la liste des fichiers dans `EternalRoutes.toc`, entre ses repères. Conversion dans `lib/addon.ts`, vérifiée par `tests/addon.test.ts`. Les identifiants saisis à la main (Zéphras, ajouts Forever) ne partent pas dans l'addon : il suit ces quêtes par leur nom et apprend leur identifiant à l'acceptation. Un parcours enregistré en jeu avec RouteProbe (priorité 10) passe avant le guide du site (priorité 1). Base de quêtes intégrée : `npm run addon:base -- <dossier de l'addon>` écrit `QuestDB.lua` (`fichierBaseQuetes`, même source : titres, niveaux, quête préalable, donneur et receveur placés, secteur des objectifs, objectifs rédigés par La Taverne, en français et en anglais, masques de classe et de race) ; l'addon s'en sert pour placer les étapes des routes RouteProbe à l'import (la base d'abord, l'enregistrement pour une quête absente de la base), afficher les objectifs et signaler un niveau ou une quête préalable manquants. Relancer les deux commandes après chaque `npm run base:quetes` ou changement des parcours relevés. Version anglaise de l'addon : `QuestDB.lua` porte aussi les noms anglais des cartes (`ns.zoneNamesEn`) et des sorts (`ns.spellNamesEn`, d'après `content/sorts-jeu.en.json`) ; les contenus propres à Forever, absents des bases libres, passent par `content/traductions-forever-en.ts` (nom du client français → nom anglais), rempli à la main avec des noms lus sur un client anglais ou une source officielle, jamais traduits par nous. L'addon ne prend ni ne rend aucune quête à la place du joueur.

## Version anglaise

Données du jeu en anglais, à côté des françaises et avec les mêmes identifiants : `content/sorts-jeu.en.json` (`npm run sorts:jeu`), `content/quetes-jeu.en.json` et `content/guide-jeu.en.json` (`npm run base:quetes -- … --en`), `objets/donnees/butin.en.json.gz` (`npm run base:butin -- … --en`), noms anglais des objets en base (`nom_en`, `description_en`, remplis à l'import) et des lieux (`content/lieux-en.ts`, `npm run lieux:en`). Les chargeurs (`lib/sorts.ts`, `lib/guide.ts`, `lib/quetes.ts`, `ouTrouver`) prennent une langue (`lib/langue.ts`, « fr » par défaut). Les heures s'affichent dans le fuseau du visiteur (`components/HeureLocale.tsx`, `lib/heures.ts`).

Pages anglaises sous `/en/` (`app/en/`, cadre `components/CadreEn.tsx`, `<div lang="en">`, menus déroulants de `NavPrincipale` avec `MENU_EN` : les pages pas encore traduites y mènent au site français, signalées « in French ») : accueil, guide de 1 à 60 (`/en/leveling-guide/<race>/<class>/`), classes avec sorts, talents et familiers, calculateur, races, compte (`/en/account/`, mêmes actions que `/compte/`, champ caché `langue`, messages traduits par `lib/messages-en.ts`). Slugs anglais, noms et correspondance des pages dans `lib/anglais.ts` (`cheminAnglais`, `cheminFrancais`, `languesDe` pour les balises hreflang des pages françaises traduites) ; une page française sans équivalent ne reçoit pas de hreflang. Les composants partagés prennent `langue` (« fr » par défaut). La clé de progression d'un guide reste celle du slug français : la même progression vaut dans les deux langues. Un navigateur réglé dans une autre langue que le français voit sur une page traduite une proposition de version anglaise (`SuggestionAnglais`, stockage de session seulement). Une nouvelle page anglaise s'ajoute aussi à `cheminAnglais`/`cheminFrancais`, au plan du site et au test `tests/anglais.test.ts`. Base d'objets (`/en/item-database/`, fiches `/en/item-database/items/<id>/`, mêmes identifiants) : les lectures du module prennent une langue (`categoriesObjets`, `chercherObjets`, `lireObjet`, `recettesObjet`), avec repli sur le français quand une colonne `_en` est vide ; catégories, ensembles, recettes et métiers en anglais sont remplis à l'import (colonnes `nom_en`, `nom_long_en`, `metier_en`, recherche sur `nom_recherche_en`) ; libellés (qualités, emplacements, liens, caractéristiques, rangs des monstres, prix « 25g 53s 55c ») dans `objets/libelles.ts`, `caracteristiques.ts` et `butin.ts`. Cartes (`/en/maps/<lieu>/`) : slug anglais tiré du nom anglais de la carte (`LIEUX_EN`, `pageLieuEn`) ; noms des donjons et raids lus dans la table `Map` du jeu (`DONJONS_EN`, `npm run lieux:en`, `nomDonjonEn`, alias pour les noms des guides qui diffèrent du jeu) ; un raid sans nom confirmé reste entre crochets. Zones, donjons, Skyborne et guides de référence (`/en/zones/`, `/en/dungeons/`, `/en/races/skyborne/`, `/en/guides/…`, quêtes de classe comprises) : textes anglais dans `content/monde-en.ts` (fiches et repères de `content/reference.ts`), à reporter quand la fiche française change, mêmes faits et mêmes crochets ; les noms de zones et de donjons viennent des fichiers du jeu (`nomZoneEn`, `nomDonjonEn`). Actualités et articles (`/en/news/`, `/en/topics/<rubrique>/`, `/en/articles/<slug>/`, même slug que l'article français) : traduits par l'IA après publication (`traduction/traducteur.ts`, consignes `traduction/consignes.ts`, tâche `npm run veille:traduire` toutes les heures, dans `npm run veille:horaire`), gardés dans la table `articles_en`. Garde-fous : seul un article en ligne se traduit, et il disparaît en anglais s'il est retiré en français ; l'avis anglais est la traduction fidèle de `avis_silfax`, jamais un avis produit sans lui ; la traduction garde les faits, les chiffres et l'unique citation ; le texte anglais passe par `markdownVersHtml` comme le français. Une traduction corrigée à la main dans l'éditeur (`/admin/veille/<id>`, bloc « Version anglaise ») n'est plus écrasée ; si le français change ensuite, l'éditeur le signale (`empreinte`). Un article pas encore traduit affiche en anglais un renvoi vers le français (non indexé), et les balises hreflang de l'article français n'apparaissent qu'une fois la traduction faite. Lettre (`/en/newsletter/`, avec ses pages de confirmation `/en/newsletter/confirm/` et de désinscription `/en/newsletter/unsubscribe/`) : l'abonné reçoit l'édition de la langue de la page où il s'est inscrit ; la Lettre anglaise s'écrit dans `/admin/lettre`, édition anglaise. Carnet (`/en/notebook/`) : les épisodes sont des articles de la rubrique « carnet », traduits comme les autres. Tableau des guildes (`/en/guilds/`, fiche, inscription, page de modification `/en/guilds/edit/<jeton>/`) : libellés anglais (`LIBELLES_GUILDE_EN`), messages traduits par `lib/messages-en.ts` ; le texte déposé par une guilde n'est jamais traduit automatiquement (il a été relu tel quel) ; la page de modification anglaise contient le secret comme la française : ni indexée ni mesurée (`cheminMesurable`). Mentions légales et confidentialité (`/en/legal-notice/`, `/en/privacy/`) : traductions de courtoisie, la version française fait foi ; tout changement de la page française se reporte dans l'anglaise. Calendrier (`/en/calendar/`, agenda anglais `/en/tavern-calendar.ics`, textes anglais dans le champ `en` de chaque échéance de `content/calendrier.ts`), communauté (`/en/community/`) et contact (`/en/contact/`). Soutenir (`/en/support/`), à propos (`/en/about/`), plan du site (`/en/sitemap/`, à compléter à chaque nouvelle page anglaise) et recherche (`/en/search/`, sur le texte anglais des articles traduits, `rechercherPubliesEn`). Toutes les pages publiques ont désormais leur version anglaise ; seules les pages d'administration restent en français.

Plan du site : `app/sitemap.ts` donne pour chaque page traduite ses deux versions avec leurs balises hreflang (`cheminAnglais`) ; il est déclaré dans `robots.txt`. Fichier de validation de Bing Webmaster Tools : `public/BingSiteAuth.xml` (ne pas supprimer).

```bash
npm run dev              # site en local (DATABASE_URL requis)
npm test                 # tests unitaires (garde-fous, classement, flux, relais)
npm run lint             # vérification des types
npm run build            # compilation de production
npm run db:migrate       # schéma de la base
npm run veille:sources   # vérifie chaque flux de config/sources.ts
npm run veille:essai     # classement du jour, sans rédaction ni coût d'API
npm run veille:quotidien # passage complet : brouillons rédigés par l'IA
npm run veille:revue     # rédige les meilleurs sujets de la dernière revue, sans refaire la collecte
npm run veille:dossier   # dossiers de référence sur 60 jours (zones-depart, donjons, zones-niveaux), sans coût d'API
npm run veille:facebook  # relais Facebook
npm run veille:lettre    # envoie la Lettre en file, par lots, dans la limite du plafond quotidien
npm run veille:horaire   # traduction puis Lettre, chaque heure à h 25 (Scalingo : cinq tâches planifiées au plus dans cron.json)
npm run veille:videos    # vidéos des Reels demandées depuis l'éditeur et des articles de moins de 7 jours (toutes les 10 minutes, conteneur L à part : jamais ffmpeg dans le conteneur du site)
npm run veille:liens     # remplace les liens Google News des sources par l'adresse directe des articles (aussi fait chaque matin)
npm run base:importer    # base d'objets depuis wago.tools, caractéristiques comprises (si nouvelle version du jeu ; --forcer, --icones)
npm run base:butin -- <dump CMaNGOS> <db_world AzerothCore>  # « où le trouver » → modules/veille/objets/donnees/butin.json.gz (fichier versionné)
npm run base:quetes -- <dump CMaNGOS> <db_world AzerothCore> # quêtes de classe et parcours de 1 à 60 → content/quetes-jeu.json (fichier versionné)
npm run base:quetes -- <dump CMaNGOS> <db_world AzerothCore> --en  # même chose en anglais → content/quetes-jeu.en.json, content/guide-jeu.en.json
npm run visuels:generer  # PNG de l'enseigne, de l'icône du site et de l'avatar de Jobwow, depuis visuels/

npm run ecrans:jeu       # écrans de chargement du jeu (config/ecrans.ts) → public/images/jeu/ecrans/, en 1600 et 800 pixels
npm run sorts:jeu        # sorts et talents de chaque classe par spécialisation (wago.tools) → content/sorts-jeu.json et public/images/jeu/sorts/

npm run icones:jeu       # icônes officielles des classes et des races, découpées dans les fichiers du jeu (wago.tools) → public/images/jeu/
npm run addon:guides -- <dossier EternalRoutes>  # guides de 1 à 60 du site → Guides/site/*.lua, Maps.lua et EternalRoutes.toc de l'addon
npm run kit:blizzard -- <dossier>  # visuels du kit officiel Blizzard → public/images/kit/ et config/kit-blizzard.ts (galerie de l'éditeur)
npm run addon:base -- <dossier EternalRoutes>  # base de quêtes intégrée de l'addon (français et anglais) → QuestDB.lua et EternalRoutes.toc
npm run carnet:video -- <dossier Warcraft Recorder>  # sur le PC de Jobwow : vidéos rangées par séance, assemblées, titre, description et chapitres YouTube
npm run addon:wow        # même chose, directement dans l'addon installé sur le PC de Jobwow (C:\WOW\world of Warcraft\_forever_\Interface\AddOns\EternalRoutes)
```

Avant tout envoi : `npm run lint && npm test && npm run build`.

## Style

Textes du site en français, ton direct et chaleureux, sans formules creuses. Les informations non confirmées restent entre crochets (`[À compléter]`) plutôt qu'inventées.
